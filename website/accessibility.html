Accessibility

Native controls, programmatic labels, visible focus and semantic errors. The limits are documented instead of implied.

Implemented semantics

RequirementImplementation
Accessible namesEvery field has a <label for> or an explicit accessible name. hideLabel is visual only.
Error associationerrorMessage sets aria-invalid="true" and is connected with aria-describedby.
Helper associationHelper text is connected with aria-describedby when no error is present.
Focus visibilityA 2px focus overlay at 2px offset, additive to the component state.
Disabled semanticsNative disabled on both PhoneInput controls; disabled suppresses error and focus treatment.
Toggle semanticsPasswordInput uses <button type="button"> with aria-pressed.
Country selectorNative <select> with an accessible name and full country names plus dial codes.
Forced coloursStylesheets include @media (forced-colors: active) rules for boundaries and focus.
Reduced motionThe documentation site honours prefers-reduced-motion.

Keyboard behaviour

  • Button: native activation with Enter and Space.
  • Input and PasswordInput: native text editing. The toggle is reachable with Tab and activated with Enter or Space.
  • PhoneInput: native select and telephone input; no keyboard trap and no custom listbox.
  • Focus order follows DOM order. The focus overlay is not clipped by the component container.

Contrast

Token validation checks text, boundary, focus and error pairs. Disabled text is excluded because inactive controls are exempt under WCAG 1.4.3 and 1.4.11.

PairTargetStatus
Body text on default surface4.5:1Pass
Control boundary on surface3:1Pass
Focus ring on surface3:1Pass
Error text on surface4.5:1Pass
Disabled text on disabled fill—Exempt

Run node tokens/check.mjs to reproduce the token contrast report.

What was validated

  • Token structure and contrast pairs: automated.
  • Contract, parity and component behaviour: automated.
  • React adapter behaviour: automated tests.
  • CLI installation and conflict handling: automated tests.
  • Documentation site structure, links and mobile layout: automated checks plus manual review.

Not certified

No formal certification. Sorleed has not been certified with screen readers, assistive technology users, or every browser and zoom combination. Automated checks are evidence, not certification.

  • No NVDA, JAWS, VoiceOver or TalkBack certification.
  • No independent WCAG audit.
  • No formal cross-browser matrix beyond the automated checks described in the repository.
  • No forced-colours manual test on every platform.
  • No claim that every consumer composition is accessible; the consumer owns labels, error copy and page structure.
