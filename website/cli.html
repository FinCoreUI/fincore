Sorleed CLI

Copy canonical source into your project. Keep it. Edit it. The CLI never silently overwrites existing files.

Commands

sorleed --help
sorleed --version
sorleed list
sorleed list --json
sorleed add <component> [--dir <path>] [--dry-run]

list shows the four components and their runtime dependencies. add copies one component into the target directory.

Available components

  • button — no extra runtime dependencies
  • input — no extra runtime dependencies
  • password-input — no extra runtime dependencies
  • phone-input — requires libphonenumber-js

Copied files

components/sorleed/<component>/index.tsx
components/sorleed/types/index.ts      (shared)
styles/sorleed/<component>.css
styles/sorleed/tokens.css              (shared)

Import tokens first, then the component styles:

import "./styles/sorleed/tokens.css";
import "./styles/sorleed/button.css";

Conflicts

  • Shared files are reused only when they are byte-identical to the canonical source.
  • A different shared file is a conflict, and the install aborts.
  • Any existing component file aborts the install before anything is written.
  • On copy failure, only files created by that run are rolled back.
  • There is no --force or --skip. Resolve conflicts deliberately.

Use --dry-run to see exactly what would be created, reused or conflict before writing anything.

PhoneInput dependency

PhoneInput needs libphonenumber-js for parsing and format validation:

npm install libphonenumber-js

Button, Input and PasswordInput do not require it.

Limitations

  • Private alpha and unpublished.
  • No browser rendering verification is performed by the CLI.
  • No interactive conflict resolution.
  • CSS imports require a bundler that supports them.
  • TypeScript consumers may need a *.css ambient declaration.

Source: cli/README.md. Tests: cd cli && npm test.
